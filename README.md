# Почему медленная CSS-анимация дрожит в Firefox и как её лечит поворот на 0,3°

> Демо: [`keytype.html`](./keytype.html) — реальный фон keytype на весь экран с переключателем угла; [`demo.html`](./demo.html) — лесенка из 7 углов с мелким текстом. Обе страницы без зависимостей (для `keytype.html` рядом нужна папка `img/`).

## Симптом

В тренажёре печати [keytype](https://keytype.pro) на странице профиля есть анимированные обои: диагональные ленты с логотипом медленно едут (≈ 8–11 px/с). В Chrome и Edge это выглядит ровно. В Firefox картинка «щёлкает» и дрожит: мелкие буквы то прыгают на пиксель, то замирают, а при взгляде на анимацию создаётся ощущение слайд-шоу. Дополнительная странность: дрожь есть и *поперёк* траектории движения.

Самое странное — масштаб:

- Ctrl + «+» (масштаб страницы): дрожит.
- Пинч-зум на тачпаде (визуальное увеличение): дрожи нет.
- Любой масштаб в Chrome/Edge: дрожи нет.

## Что мы пробовали и что не помогло

Слои в проекте двигаются компоновщиком через `transform: translate3d(...)`. Сначала мы по очереди проверили гипотезы, и ни одна не сработала:

| Гипотеза | Итог |
| --- | --- |
| Частота шагов `steps()` (режим программной отрисовки) | не причина |
| Размер слоя слишком большой | не причина |
| `zoom: 1.35` на контейнере | не причина |
| Округлить концы пути до физических пикселей | стало хуже |
| Зеркальный путь, чтобы обе оси имели одинаковую фазу | не помогло в Firefox |
| `will-change` убрать / оставить | не помогло |
| `scale(1.002)` | не помогло |
| `background-position` вместо transform | не помогло |
| `rotate(.002deg)` | не помогло |
| **`rotate(.3deg)`** | **плавно** |
| `<canvas>` | плавно |

(Таблица собрана по A/B-тестам владельца проекта в Firefox; в Chromium разница между вариантами не видна, потому что дрожи там нет вообще.)

## Что нашлось в баг-трекере Mozilla

Сначала версия: Firefox (WebRender) привязывает («снэпит») к целым физическим пикселям слой, который двигается *чистым сдвигом*. Медленный дрейф 8 px/с превращается в щелчки по 1 px, а если у осей X и Y разная дробная фаза, то они переключаются в разные кадры, отсюда дрожь поперёк траектории. При пинч-зуме привязка не применяется, поэтому там плавно.

Подтверждения, которые удалось найти (все через поиск, исходники WebRender мы не разбирали **[проверить]**):

- [Bug 1435094](https://bugzilla.mozilla.org/show_bug.cgi?id=1435094): инженер Mozilla пишет, что WebRender отключает привязку к пикселям для элементов с не осево-выровненным преобразованием, а прежний Gecko отключал её при любом преобразовании, кроме translation.
- [Bug 663776](https://bugzilla.mozilla.org/show_bug.cgi?id=663776): ступенчатое движение в переходах объяснено привязкой; репортёр отмечает, что добавление любого `rotate()` сглаживает анимацию.
- [Bug 739176](https://bugzilla.mozilla.org/show_bug.cgi?id=739176): нет субпиксельного рендеринга при переходах `translate`.
- [Bug 1512010](https://bugzilla.mozilla.org/show_bug.cgi?id=1512010): текст при анимации «подёргивался» из-за привязки позиций; починили тем, что анимируемое больше не привязывают.
- Обход давно известен практикам: [тема на форуме GSAP](https://gsap.com/community/forums/topic/12760-animation-slowjerky-not-smooth-in-firefox/) (поворот ≈ 0,01°), [форум Tumult](https://forums.tumult.com/t/resize-translate-animations-stuttery-especially-on-firefox/6347) (`rotate(0.1deg)`).

То есть механизм: чистый сдвиг ⇒ слой привязывается к пикселям ⇒ щелчки. Небольшой поворот делает преобразование не осево-выровненным ⇒ привязка отключается ⇒ движение субпиксельное.

## Решение

```css
@keyframes plv {
  from { transform: rotate(.3deg) translate3d(0, 0, 0); }
  to   { transform: rotate(.3deg) translate3d(var(--dx), var(--dy), 0); }
}
.layer {
  position: absolute;
  --m: max(12px, 1vw);               /* поле под углы, которые заметает поворот */
  left: calc(var(--x0) - var(--m));
  top:  calc(var(--y0) - var(--m));
  width:  calc(100% + var(--w) + var(--m) * 2);
  height: calc(100% + var(--h) + var(--m) * 2);
  will-change: transform;
  animation: plv var(--d) linear infinite;
}
```

Нюансы:

1. Слой делаем больше контейнера на размер плитки + поле `--m`, иначе повёрнутые углы обнажают фон.
2. Путь движения совпадает с вектором решётки узора, чтобы цикл замыкался без шва. Трансляция идёт *внутри* повёрнутой системы координат, поэтому узор повёрнут вместе со слоем, а путь остаётся вдоль его решётки.
3. Порог лежит между `.01deg` и `.05deg`: на демо-лесенке углов в Firefox плавно начинается с `.05deg` (`.002deg` и `.01deg` — дрожат). В проекте оставлен `.3deg` — запас в 6 раз над порогом; визуально разницы между `.05` и `.3` почти нет (одному наблюдателю `.3` показался чуть плавнее, но это субъективно). Тест: один человек, один Firefox **[проверить на других версиях/ОС]**.

## Что осталось неизвестным

- Точный допуск, при котором WebRender считает преобразование осево-выровненным.
- Поведение в текущих версиях Firefox: баги, на которые мы ссылаемся, старые; подтверждение — только наши тесты на конкретном устройстве.
- У части людей (по форумам) поворот не помогал, так что это не универсальное лекарство.

## Как проверить самому

Самый наглядный пример — [`keytype.html`](./keytype.html): настоящий фон проекта (два слоя ленточного логотипа едут навстречу друг другу) и кнопки 0° / 0,01° / 0,05° / 0,3°. Если у вас Firefox, при 0° края букв дрожат и «щёлкают», на 0,3° плывут.

Лесенка углов — [`demo.html`](./demo.html) в Firefox и Chrome. Семь плиток движутся с одинаковой скоростью, отличается только угол `rotate()`. Если на плитке 0° буквы «щёлкают», а на 0,3° плывут, ваш Firefox ведёт себя так же, как наш.
